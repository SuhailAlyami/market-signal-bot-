# وكلاء Gemini داخل المستودع

| الوكيل | متى يعمل | ماذا يفعل |
| --- | --- | --- |
| `gemini-review` | عند فتح PR، أو عند تعليق المالك `/gemini` على أي PR | مراجعة محايدة (دور Goldfish) تُرسل إلى Telegram |
| `gemini-weekly-audit` | كل أحد 09:41 بتوقيت الرياض، أو يدوياً | يدقق محوراً واحداً كل أسبوع (البيانات ← التنبيهات ← البحث ← سير العمل ← الاختبارات) ويرسل الملاحظات واقتراح PR واحد إلى Telegram |

- المحرك: Gemini CLI من Google، وهو مفتوح المصدر (Apache-2.0)، ويعمل بمفتاح AI Studio المجاني.
- المفتاح: يُقرأ من السر `GEMINI_API_KEY`، وإن لم يوجد فمن `GOOGLE_API_KEY`. إن لم يوجد أي منهما يتخطى الوكيل عمله بدون فشل.
- اختيار النموذج اختياري: متغير المستودع `GEMINI_MODEL`.
- قناة الإشعار الوحيدة هي **Telegram** (مجانية، الأسرع، دائمة)، فلا تعليقات ولا Issues ولا بريد من الوكلاء. المفتاح `TELEGRAM_NOTIFY=off` يُسكتها مثل باقي المشروع.
- الأمان: خطوة Gemini لا ترى أسرار GitHub ولا Telegram، وخطوة الإرسال لا ترى مفتاح Gemini. الوكلاء لا يدفعون كوداً، فالتنفيذ يبقى بقرار المالك.
- الاستهلاك: نحو 2–3 دقائق Actions لكل مراجعة، ونحو 3 دقائق للتدقيق الأسبوعي.
