# تشغيل سهيل هنتر ببيانات IBKR والمتابعة من الآيفون

يمكن أن يبدأ GitHub البرنامج على كمبيوترك عبر Self-hosted runner، بينما
تتابع النتائج من الآيفون. يبقى الكمبيوتر متصلاً بالإنترنت ويحتفظ بتفويض IBKR.
GitHub لا يتحول إلى مزود أسعار، وربط IBKR في ChatGPT لا يفوّض برنامج المستودع.

## الحالة الفعلية

- جلب الأسعار النشط في المشروع يستخدم IBKR دون رجوع إلى Yahoo.
- `hunter_session.py` يشغّل الكواشف أثناء نيويورك بإيقاع مستهدف كل 60 ثانية.
- يُطلب ES وNQ مرة واحدة لكل دورة وتُشارك النتيجة بين الكواشف.
- تُسجّل أوقات الوصول الفعلية والتأخير والأخطاء. تمنع البيانات المجمدة والمتأخرة.
- التشغيل المتصل يحتاج تفويضاً محلياً ناجحاً؛ لم يُنشأ runner أو تفويض على كمبيوترك تلقائياً.
- النماذج بحثية: نجاح التشغيل لا يثبت كشف الانفجارات السعرية أو الربحية.
- التنبيهات والأوامر موقوفة. لا يلزم اشتراك TradingView لهذا المسار.

## أول تشغيل من الكمبيوتر

نزّل المستودع أو استنسخه وافتح الطرفية داخل مجلده. تحتاج Python 3.11.
الأوامر التالية على Linux أو macOS، أو Ubuntu داخل WSL على Windows.
تخزين OAuth الحالي يعتمد على أذونات POSIX؛ تشغيله مباشرةً على Windows
يحتاج تهيئة حماية ملفات مناسبة لذلك النظام، ولم يُتحقق منه على جهازك.

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python hunter_session.py --authorize --once
.venv/bin/python ibkr_feed_preflight.py
```

أمر التفويض يعرض رابط IBKR. افتحه في متصفح **الكمبيوتر نفسه** وسجّل الدخول
وأكمل الموافقة هناك. لا ترسل كلمة المرور أو رموز الجلسة في المحادثة أو GitHub.
الخادم المحلي يستقبل نتيجة الموافقة. يحتفظ البرنامج بالتفويض خارج المستودع.
لا تفعّل `--authorize` داخل GitHub Actions؛ يمنعه البرنامج صراحةً.

`AUTHORIZED_CONNECTION` يعني نجاح اتصال MCP، و`AUTH_PRESENT_UNVERIFIED`
يعني وجود تفويض محلي. لا تعني أي منهما أن كل أسعارك لحظية؛ يتحقق البرنامج
من ذلك عند كل جلب. قبل الجلسة تظهر `WAITING_FOR_NY_OPEN` دون طلب أسعار.

للتشغيل المحلي بعد التفويض:

```bash
.venv/bin/python hunter_session.py
```

اترك العملية والكمبيوتر يعملان دون سكون أثناء الجلسة. ينتظر البرنامج الافتتاح،
ويستخدم تقويم NYSE للعطلات والتوقيت الصيفي والإغلاق المبكر، ويتوقف بعد الإغلاق
أو بعد 16 ساعة كحد افتراضي. `Ctrl+C` يوقفه. لا تشغّل نسخة محلية وأخرى عبر
GitHub في الوقت نفسه؛ قفل المجلد يمنع النسخ المتزامنة داخل مجلد الحالة نفسه.

## بدء التشغيل من GitHub والآيفون

هذه خطوة إعداد لمرة واحدة على الكمبيوتر، ولا تحتاج نقل أسرار IBKR إلى GitHub:

1. افتح إعدادات المستودع في GitHub ثم **Actions → Runners → New self-hosted runner**.
2. اختر نظام بيئة Python المستخدمة للتفويض واتبع أوامر التسجيل التي يولّدها GitHub. إذا استخدمت WSL فاختر Linux وشغّل runner داخل Ubuntu نفسها. أضف label باسم `ibkr-market-data`.
3. شغّل runner **بنفس مستخدم النظام الذي أكمل تفويض IBKR** حتى يجد ملفات التفويض الخاصة به. عند التشغيل التفاعلي اترك `run.cmd` على Windows أو `run.sh` على Linux/macOS يعمل.
4. من إعدادات المستودع افتح **Secrets and variables → Actions → Variables** وأضف Repository variable: الاسم `IBKR_RUNNER`، والقيمة `ibkr-market-data`.
5. أوقف نسخة `hunter_session.py` المحلية إن كانت تعمل؛ ستبدأ GitHub نسختها الخاصة.
6. من الآيفون افتح **Actions → NY IBKR continuous research — no alerts → Run workflow** واختر `main`.

الـ workflow الموجود في `.github/workflows/ibkr_session.yml` يستهدف هذا runner،
ويفحص وجود التفويض ثم يشغّل جلسة تصل إلى 8 ساعات. يبدأ جدولُه الاسمي الساعة
13:25 UTC في أيام الأسبوع، قبل افتتاح نيويورك صيفاً وشتاءً؛ وقد يتأخر تشغيل
GitHub. ينتظر البرنامج الافتتاح الفعلي ثم يتوقف عند الإغلاق. يُعطّل مسار
الفحص القديم كل خمس دقائق عندما تضبط `IBKR_RUNNER` لمنع تكرار التشغيل.

لم يُضبط متغير المستودع أو يُسجّل كمبيوترك بواسطة هذا التعديل. إذا لم يضبط
المتغير تتخطى GitHub جلسة الكمبيوتر بدلاً من افتراض وجود اتصال. وإذا غاب
التفويض يظهر `AUTHORIZATION_REQUIRED`؛ وإذا انتهى تفويض أثناء الرصد تتوقف
العملية وتحتاج تجديده محلياً.

## قراءة النتائج من الآيفون

بعد انتهاء التشغيل افتح **Artifacts** في صفحة الـ run ونزّل `ibkr-ny-…`.
يحتوي على:

- `ibkr-runtime.json`: هل يوجد تفويض على هذا الجهاز؟
- `ibkr-session/session-heartbeat.json`: حالة آخر دورة، حداثة البيانات وحالة الكواشف.
- `ibkr-session/shadow-ibkr.jsonl`: سجل الكاشف الأساسي ونتائجه البحثية.
- `ibkr-session/ny/`: الشموع المرصودة أول مرة وسجل المرشحين المجمدين.

ملفات التفويض لا تدخل هذه المرفقات. المرفقات تُرفع عند نهاية الـ job، وليست
لوحة أسعار حية أو تنبيهات فورية. سجل GitHub أثناء التشغيل يعرض حالة كل دورة.
إيقاع 60 ثانية مع زمن الطلبات والتأخير لا يضمن التقاط الحركة في أول دقيقة؛
يجب الحكم على وقت الرصد الحقيقي ونتائج الاختبار اللاحق، ولا تزال جودة الكاشف
بحاجة إلى إثبات مستقل في السوق.
