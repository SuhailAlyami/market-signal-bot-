# قناة الإشعار: الأولى التي تعمل فقط

قاعدة المالك (2026-11-24): الإشعار يكون عبر قناة واحدة هي أول قناة تحقق الشروط الثلاثة: **مجانية، الأسرع، دائمة**. يجرّب النظام القنوات بالترتيب ويتوقف عند أول قناة تنجح، ولا يستخدم البقية.

| الترتيب | القناة | متى تُستخدم |
| --- | --- | --- |
| 1 | Telegram | دائماً أولاً: مجانية، تصل خلال ثوانٍ، دائمة |
| 2 | Issue في GitHub | فقط إن فشل Telegram أو لم تكن أسراره موجودة. يصلك تنبيهه من تطبيق GitHub أو بريده حسب إعداداتك |
| 3 | بريد SMTP | فقط إن فشل الاثنان السابقان، وبشرط وجود الأسرار `SMTP_HOST`, `SMTP_USER`, `SMTP_PASSWORD`, `NOTIFY_EMAIL_TO`، و`SMTP_PORT` اختياري (الافتراضي 587). مثال مجاني: Gmail بكلمة مرور تطبيق |

- الكود: `range_alert/notify_chain.py`، تستدعيه `daily_range.send`، وكل إرسال في المشروع يمر عبرها: التنبيه اليومي، التقييم المسائي، TradingAgents، ووكلاء Gemini.
- `TELEGRAM_NOTIFY=off` يُسكت كل القنوات.
- كله يعمل آلياً من GitHub Actions، ولا يعتمد على أي جلسة خارجية.
- حدٌّ معروف: إن نفدت دقائق Actions فلا يعمل أي job، فلا تستطيع أي قناة الإبلاغ عن ذلك. علامة الخلل حينها غياب رسالة range-alert اليومية.
