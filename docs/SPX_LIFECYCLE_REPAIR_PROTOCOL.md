# إصلاح دورة حالات SPX — قبل قياس الأثر

الأساس `dd8ab09d0ab7c5251e25b01be375687bf4d5c2e9`؛ لا تُعدّل عتبات الاستعداد أو تعريف الحركة أو جدول التهدئة أو النتائج الأصلية. تبقى `lifecycle` الأصلية مرجعًا مجمدًا. تُضاف `lifecycle_safe` بإصدار مستقل للمقارنة فقط، بلا ربط إنتاجي أو إشعارات.

العيوب المحددة من قراءة الكود، قبل إعادة قياس النتائج:

- نافذة التأكيد/الخروج تستعمل عدد الصفوف، فتسمح بسيناريو عبر دقائق مفقودة أو جلسة مختلفة.
- لا تفحص الحالة القائمة صلاحية السياق الحالي قبل التأكيد.
- فحص التأكيد يسبق الإبطال والمهلة؛ فيمكن قبول تأكيد متأخر أو مع إبطال على الصف نفسه.

القواعد التصحيحية الثابتة:

1. الوقت الفعلي UTC، قرار كل صف = بدايته + دقيقة. انتقال تاريخ نيويورك أو مسافة ليست دقيقة واحدة أو سياق غير صالح يُنهي الحالة عند أول قرار مُلاحظ، بلا اختلاق قرار داخل الفجوة. CANCEL للاستعداد، EXIT للمؤكد، والسبب `context_discontinuity`.
2. عند سلامة السياق تُفحص كَسرة الإبطال أولًا، ثم الاستعداد المعاكس. لا تأكيد في أي منهما. لا إعادة تسليح في صف أُبطل فيه سيناريو.
3. تأكيد الاتجاه نفسه مسموح فقط بعد الاستعداد وخلال ثلاث دقائق فعلية شاملة الحد الثالث، ما دام لا إبطال. في الدقيقة الثالثة بلا تأكيد يُلغى الاستعداد؛ بعد الثالثة يُلغى ولو وصل مرشح.
4. خروج المؤكد عند الإبطال، أو مرشح معاكس، أو عشر دقائق فعلية من التأكيد. لا إعادة تسليح في صف الخروج.
5. أول صف بعد انقطاع يمكنه الاستعداد فقط إذا كان سياقه صالحًا وبعد إنهاء حالة سابقة لا يُعاد التسليح في الصف نفسه. لا تغيير في شروط directions أو في signal_schedule أو cooldown.

القياس: قارن انتقالات النسختين على جميع شرائح Oct20/21/22 المستهلكة نفسها مع المقاييس الصارمة 0/1/2 دقيقة. أبلغ الفروق حتى لو كانت صفرًا أو سلبية؛ لا اختيار نموذج ولا فتح احتجاز ولا إعادة تعديل بعد النتيجة. فحص الجلسات المستهلكة تشخيص هندسي فقط، ولا يثبت أفضلية. الحالة NOT_READY والتنبيهات والأوامر معطلة.
