# عامل البحث المحلي — إعداد وليس إثبات كشف

بُني لتشغيل Codex CLI من مهمة Windows باسم `Suhail SPX Research` عند تسجيل
الدخول وكل 15 دقيقة مع توفر الشبكة. يعمل في worktree منفصل على
`research/local-spx-agent`، ولا يبدّل فرع المستخدم أو يدمج main. التشغيل يتوقف
عند إطفاء الجهاز أو نومه، ويستأنف بعد تشغيله وتسجيل الدخول. عودة الاتصال تُفحص
في الدورة التالية وليست ضمان تشغيل في اللحظة نفسها. لا حاجة إلى Remote Tunnel.

من Terminal في النسخة المحلية من المستودع بعد تحديث فرع البحث الذي يحتوي هذه الملفات:

```powershell
powershell -NoProfile -File .\tools\install_spx_agent.ps1
```

يتطلب Python وGit وCodex CLI مثبتًا ومصادقًا بحساب المستخدم، وصلاحية دفع GitHub
العادية الموجودة. الإضافة داخل VS Code وحدها ليست CLI. السكربت لا يثبت خدمات
مدفوعة ولا يقرأ رموز الدخول ولا يحتاج تشغيل VS Code كمسؤول. هذه المحادثة لم
تنفذ المثبّت على جهاز المستخدم، ولم تثبت وصول العامل إلى Gateway المحلي.

السقف دورتان ذكيتان في اليوم UTC، ودورة بحد أقصى 15 دقيقة وبين الدورات ساعة.
هذا سقف استدعاءات وليس ضمان عدد توكنات أو تكلفة؛ يخضع لرصيد الحساب. لا التفاف
على الحدود: فشل Codex أو المصادقة يوقف العامل بحالة BLOCKED بدل إعادة المحاولة
المستمرة. تُحفظ الحالة قبل الاستدعاء، وقفل نظام التشغيل يمنع التزامن. انقطاع
الشبكة قبل الاستدعاء لا يستهلك دورة. الدفع المتعذر يُعاد قبل أي عمل جديد.

كل دورة تقرأ RESUME.md وتحفظ تقدمًا صغيرًا واختباراته ونتائجه الموجبة والسالبة
في commit على فرع العامل. يمنع البرومبت التداول والتعديل الإنتاجي والتفعيل
والأسرار وإعادة تدوير العينات، وهذه قيود تعليمات وليست عزلًا أمنيًا شاملًا
لعميل Codex؛ يعتمد التنفيذ أيضًا على sandbox وصلاحيات جهاز المستخدم.

WAIT_DATA/NOT_READY ينتظر تغير ملف `raw.json` تحت artifacts أو .hunter-state؛
لا يجمع العامل وحده بيانات أثناء هذا الانتظار. الدورة الأولى تفحص الجامع
المحلي الموجود وتوثق أمر الجمع المناسب. لا يُستهلك رصيد لمجرد مرور ساعة.
CONTINUE يستأنف خطوة ملموسة ضمن السقف. CANDIDATE_FOR_REVIEW يوقف العمل للمراجعة
ولا يعني نجاحًا تجاريًا. نجاح الكشف لا يضمن الربح ولا يُعلن من نتيجة واحدة.

الحالة والسجلات الخاصة في `%LOCALAPPDATA%\SuhailHunterResearch`، خارج المستودع؛
لا ترفع private.log لأنه قد يحتوي سياقًا محليًا. استرد الملفات غير الملتزمة
عند الفشل قبل الاستئناف، ولا تحذفها. الاستئناف لا يمحو سقف الاستخدام:

```powershell
python ..\suhail-spx-agent\tools\spx_research_agent.py --repo ..\suhail-spx-agent --state "$env:LOCALAPPDATA\SuhailHunterResearch" --resume
```

للإيقاف أنشئ STOP في مجلد الحالة، وللاستئناف احذفه. لإزالة الجدولة:

```powershell
Unregister-ScheduledTask -TaskName 'Suhail SPX Research' -Confirm:$false
```

تحقق محليًا من `Get-ScheduledTaskInfo -TaskName 'Suhail SPX Research'` ومن
state.json ومن آخر commit بعيد. بناء العامل واختبار وحداته في بيئة Linux لا
يثبت تنصيبه على Windows ولا وصوله للبيانات ولا جودة الكاشف. لا تُعلن هذه الأمور
إلا بعد سجلات التشغيل الفعلية.

مرجع أوامر Codex الرسمي: https://learn.chatgpt.com/docs/non-interactive-mode

## تنبيه الحاجة إلى تدخل المستخدم

أصبح العامل يطلب إشعار Windows محليًا عند WAIT_DATA أو BLOCKED أو الحاجة
لمراجعة نتيجة. لا يطلب فتح IB Gateway إلا عند needs_gateway=true بناءً على
دليل في الدورة؛ نقص جلسات كاملة أو إغلاق السوق أو FROZEN وحدها لا تثبت ذلك.
في بقية انتظار البيانات يوضح أن سبب الحاجة إلى البوابة لم يتأكد. النص ثابت
بالعربية ولا يتضمن رسائل المزود الخاصة. لا Telegram ولا خدمة مدفوعة.

يُحفظ الطلب ووقت الرياض في attention.json وattention.txt داخل مجلد الحالة
الخارج عن المستودع. لا يكرر طلبًا واحدًا طالما لم يتغير السبب أو تنته حالة
الانتظار. فشل طلب النافذة يحفظ النص ويحاول بعد ساعة، دون تشغيل Codex أو إنفاق
حصته. بعد التعافي يمكن للطلب نفسه أن يظهر مرة أخرى إذا عاد العائق.

الإشعار يستخدم NotifyIcon الخاص بويندوز في جلسة المستخدم المسجّل؛ إعدادات
الإشعارات/عدم الإزعاج قد تمنع ظهوره. popup_requested تعني طلب العرض فقط ولا
تثبت أن المستخدم رآه. الهاتف لا يتلقى هذا الإشعار. أنشئ STOP إذا أردت إيقافه.
الاختبارات محاكاة للعرض، ويلزم اختبار واحد على Windows:

```powershell
python .\tools\spx_research_agent.py --repo . --state "$env:LOCALAPPDATA\SuhailHunterResearch" --test-notification
```

تحتاج النسخة المحلية من العامل إلى تحديث هذه الملفات؛ دفع الكود إلى GitHub
لا يثبت تطبيقه في المهمة المثبتة. لا تقتل دورة جارية، ولا تمس التقدم المحلي؛
دع Codex يستورد التحديث بعد نهاية الدورة ثم ينفذ اختبار العرض، ويؤكد النتيجة.
عرض التنبيه لا يستأنف WAIT_DATA وحده؛ تابع الجمع من Codex، أو أضف raw.json
الجديد. كما أن --resume يحافظ على سقف الاستخدام والتهدئة.
