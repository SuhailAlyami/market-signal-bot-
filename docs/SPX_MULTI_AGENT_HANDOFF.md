# توزيع عمل الأدوات المحلية لتطوير SPX

هذه تعليمات تسليم جاهزة، وليست ادعاء تشغيل Antigravity أو AionUI من هذه
المحادثة. يستخدم كل تطبيق النموذج المتاح المصادق مسبقًا ضمن حصته؛ لا يُنشأ
API key ولا اشتراك جديد تلقائيًا. لا تُرفع الأسرار ولا سجلات الحساب إلى أي وكيل.

Codex هو منفذ الدمج والاختبارات؛ يستمر في الفرع research/local-spx-agent.
قبل أي تجربة اقرأ RESUME.md وAGENTS.md ونتائج NOT_READY الحالية. لا تختَر أفضل
مثال وتتجاهل البقية، ولا تعِد استخدام العينة المستهلكة كاحتجاز مستقل.

## مهمة Antigravity: تدقيق مستقل للبيانات والسببية

افتح نسخة منفصلة من مستودع SuhailAlyami/market-signal-bot- على فرع
research/audit-data-causality. اقرأ آخر RESUME.md. افحص مسار SPX النقدي فقط:
تطابق العقد والمصدر، timestamps المزود مقابل وقت الاستلام ووقت القرار،
الشموع غير المكتملة، فجوات الجلسة، DST، التقويم، السببية، تسرب المستقبل
واستقلال الاحتجاز. لكل عيب أعط ملفًا ودالة وطريقة إعادة إنتاج واختبارًا
يفشل قبله. ميّز المؤكد عن المشتبه. احفظ docs/AGENT_DATA_AUDIT.md والتجارب
المحددة على فرعك في GitHub، وأعد الرابط وSHA. لا تغيّر الإنتاج أو شروط
التأهيل، ولا حسابات/أوامر/أسرار/Telegram. لا دمج تلقائي.

## مهمة وكيل AionUI الأول: فرضية واحدة قابلة للإبطال

اقرأ نتائج SPX المنشورة والنماذج المجربة. اقترح فرضية سعرية واحدة فقط
تختلف فعليًا عن الفرضيات الفاشلة، مع تعليل القابلية للكشف قبل بداية الحركة.
اكتب docs/AGENT_HYPOTHESIS.md على فرع research/hypothesis-candidate قبل أي
نتائج: تعريف الحدث، مدخلات متاحة عند القرار، قواعد ثابتة، حدود بحث التدريب،
baseline بسيط، تقسيم زمني، embargo، بيانات مستهلكة/مستقلة، بوابات الجودة
الأصلية وميزانية تجارب محدودة. إذا لا توجد بيانات مستقلة فقل WAIT_DATA؛ لا
تدّعِ تقييمًا. احفظ commit وأرسل SHA إلى Codex. لا تعدّل كاشف الإنتاج.

## مهمة وكيل AionUI الثاني: مراجعة النتائج

اعمل قراءة فقط، دون تعديل أو إعادة اختيار عتبات، على commit التنفيذ الثابت.
راجع تطابق البروتوكول والنتائج والتواريخ والبصمات، المقام الذي تحسب عليه
الدقة والاستدعاء، السبق الصارم، الإنذارات غير المطابقة، الحركات المفقودة،
تأخير الوصول واستقلال العينة. افحص الأمثلة السلبية كما الإيجابية. اكتب
docs/AGENT_RESULT_REVIEW.md على فرع research/result-review بقرار ACCEPT/
REJECT/INSUFFICIENT_EVIDENCE ومبررات قابلة لإعادة الإنتاج. ACCEPT لا يعني
ربحًا أو تفويض نشر أو تداول. احفظ GitHub وأعد SHA.

## مهمة Codex: التنفيذ المنضبط

استورد تقارير الوكلاء من SHAs المعلومة بعد مراجعتها، وليس من ملخص شفهي.
لا تغيّر ملفات عمل وكيل آخر ولا تستخدم نفس worktree لعميلين يكتبان معًا.
نفّذ إصلاحات مؤكدة أولًا واختبرها. للفرضية الجديدة ثبّت البروتوكول قبل
القياس، وابحث في التدريب فقط، ثم قيّم التحقق والاحتجاز مرة واحدة وفق
البروتوكول. احفظ جميع النتائج والتقدم؛ عند نقص الدليل ابق NOT_READY.
لا تداول، ولا تفعيل أو نشر تجريبي، ولا خدمات مدفوعة. أخبر المستخدم إن احتجت
فتح البوابة عبر needs_gateway، ولا تحوّل ردًا متفائلًا من وكيل إلى دليل نجاح.

تشغيل عدة عملاء لا يجعل العينة المستهلكة مستقلة ولا يضمن أفضل نسخة؛ فائدة
التوزيع هي اختلاف المهام والمراجعة وقابلية إعادة الاختبار، مع سقف لكل تجربة.
